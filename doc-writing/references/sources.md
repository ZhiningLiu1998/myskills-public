# Sources

This skill is an independently written synthesis. The sources below informed
it; none of their text is reproduced. Revisit them when revising the skill.

- [anthropics/skills: doc-coauthoring](https://github.com/anthropics/skills/blob/00756142ab04c82a447693cf373c4e0c554d1005/skills/doc-coauthoring/SKILL.md):
  transferring the author's context before drafting, surgical edits instead of
  full rewrites, and testing the document with a reader that lacks the
  conversation's context. Its fixed question counts, brainstormed option lists,
  per-section approval, and repeated review loops were not adopted; this skill
  asks only consequential questions and proceeds without stage approvals.
- [google/styleguide: documentation best practices](https://github.com/google/styleguide/blob/9b15a1d71f9591fcb3f30f1e4f4dc77e94e7eef0/docguide/best_practices.md):
  short, accurate documents, the simplest example first, linking instead of
  duplicating other guides, and keeping design documents as decision records
  rather than descriptions of current behavior. Its advice to delete dead
  documentation by default and to submit fixes to other teams' docs was not
  adopted.
- [Diátaxis](https://github.com/evildmp/diataxis-documentation-framework/tree/957c09ca40b4a1edc23874f713e01937d50d54d5/source)
  (compass, how-to guides, explanation): choosing content by whether the reader
  needs to act or understand, goal-oriented how-to guides, and keeping
  explanation, steps, and reference apart. This skill allows those parts as
  sections of one document instead of requiring separate documents.
- [Michael Nygard's decision record template](https://github.com/architecture-decision-record/architecture-decision-record/blob/f044e0d79d613d80aa88201a720e9c9cf6f08411/locales/en-us/templates/decision-record-template-by-michael-nygard/index.md):
  context, decision, status, and consequences, used in the proposal pattern as
  guidance rather than a mandatory template.
